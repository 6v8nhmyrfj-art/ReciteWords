**尚未正式替换旧站。** 腾讯云域名出现备案阻断，已回退到 GitHub Pages + Supabase 继续提供服务，旧库写入限制已解除。腾讯云后端保留为待启用环境，认证、REST 与业务函数已停止；公网 Nginx 恢复准备页面。没有将 GitHub 入口跳转到被阻断域名。

## 已完成

- 域名及 www 的 A 记录正确；HTTPS 证书及自动续期已配置。
- 在腾讯云部署 PostgreSQL 17、GoTrue、PostgREST、Edge Runtime 和内部 Nginx 网关。数据库及网关未直接暴露公网端口。
- 账号认证数据及 21 张业务表恢复成功；最终同步时 23 张表逐表行数与内容摘要一致。
- 44 个原账号的 UUID 与密码哈希保留。原密码没有被重置；在隔离副本测试使用的临时密码、教师角色已被最终源数据恢复覆盖。
- 修复自建默认授权过宽的问题：96 个对象授权和 14 条列级授权按源库重建并验证。目标 postgres 角色取消超级用户，保留与源库相同的 RLS bypass 能力。
- 教师重置、首次改密、创建学生、学生数据隔离、匿名访问拒绝、课堂抽查、口头判分防伪造、周任务、幂等与续测检查通过。

- 手机尺寸浏览器检查通过，无横向溢出，登录保持正常。公网浏览器曾成功登录，但随后国内直连出现腾讯云备案拦截，因此没有据此宣布正式上线。
- 40 路并发、80 次周任务请求全部成功；服务器内部测得 P95 0.211 秒。此数字不包含学生手机网络、全班下载词库或语音接口耗时。
- 英文样本音频经迁移后的业务函数成功识别。语音与云端语义服务仍使用现有 Cloudflare，并未迁移为腾讯云 ASR。

## 阻断证据与安全回退

域名 HTTP 访问被重定向到腾讯云 `dnspod.qcloud.com/static/webblock.html`。该页面的公开备案状态接口返回 GovStatus=false、LandedStatus=false、AuditTicket=false、Ban=false，即尚未备案、未接入、无备案申请，并非内容封禁。

发现阻断后先恢复新站准备页、停止新端业务服务，删除专用验收账号，再比较新旧 23 张表。确认全部一致后解除旧库写入隔离，验证剩余冻结触发器为 0，旧库写入事务可以正常执行。没有丢弃新端正式学习记录。

## 继续切换的前置条件

1. 域名在腾讯云完成适用的 ICP 备案/接入；主体身份、人脸及短信核验需要本人完成。
2. 从国内直连核查 HTTP 最终地址和 HTTPS，不能仅以代理网络或单个浏览器可访问为依据。
3. 旧站持续产生数据，必须重新备份同步，不得直接启用本次保存的数据库副本。
4. 重新执行授权与数据核对、登录和保存测试，通过后才启用正式 Nginx 配置、更新 GitHub 入口。
5. 国内语音服务需要另行接入；未完成之前明确保留 Cloudflare，不能声称所有云依赖已迁走。
