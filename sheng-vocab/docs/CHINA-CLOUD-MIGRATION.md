## 目标路线

第一阶段使用同一云厂商：Linux主机运行自建 Supabase兼容栈（PostgreSQL、Auth、PostgREST/RPC、函数运行时）+ HTTPS反向代理 + 静态网站。
迁移的是 Supabase托管服务，保留开源组件不是继续依赖海外云。官方Docker方案是基础模板，不代表本项目已经可直接一键部署。
源端为PG17，目标优先兼容PG17；禁止未经恢复演练降至PG15。普通腾讯云/阿里云PostgreSQL并不附带auth.uid、认证角色、PostgREST和函数网关，不能仅改数据库地址。
后续可将数据库拆到云厂商托管PostgreSQL；先测试权限和扩展兼容性。
不建议同时购买两套云资源。生产实例配置需在选定组件、测试恢复并压测后确定；现阶段不报未经核验的价格和配置保证。

## 备份与恢复

1. 使用官方平台→自建恢复流程取得一致数据库备份（结构、业务、Auth、角色）。需源数据库管理连接；MCP查询权限不能代替pg_dump连接凭据。
2. tools/export-business.py已升级v4，含21表，在同一只读可重复读事务导出；输出权限600，禁止覆盖。兼容校验v1–v3文件。
3. JSON只是便携业务副本，不含认证密码哈希，也不含结构、对象存储二进制和服务器密钥；不能独立恢复登录。
4. Auth按官方恢复流程保留user UUID、identities和密码哈希；不要求学生提供明文密码。迁移后原密码是否可用以实际登录验收为准，预计要求重新登录。
5. 核对storage.buckets/objects是否实际存储文件；有则单独复制二进制并对比数量/校验值。Auth配置、SMTP、重定向、密钥单独迁移。
6. 备份只放权限受控目录和加密对象存储，不写入公开仓库。正式迁移前做一次空目标恢复演练。

## 验收与切换

- 每表行数、主键集合、外键、词书words顺序、任务快照、学习历史、周任务、每日三轮进度一致。
- 教师与两位不同班学生测试权限，不能访问他人成绩或认定过关；匿名请求拒绝。
- 登录、初次改密、教师重置、词库导入、学习、复习、课堂、每日抽查、续测、断网重复提交全部验证。
- 真手机测试Safari/微信/Android浏览器的中文与英文录音、超时和云端错误；不宣称ASR是专业发音评分。
- 40人并发场景压测，确认API延迟、错误率、ASR费用和配额，再定机器规格。
- 切换窗口冻结旧端写入，等待待保存队列同步，最终备份/恢复/校验，切域名与API，再开放目标写入。旧端只读。
- 回滚先停止新写入并导出新端增量，再决定回放；不能直接切回旧库丢弃学生新记录。
