# 发音前置流程（开发中，未启用）

已实现纯状态模块、录音组件和紧凑页面组件。尚未接入生产数据库或自动评测，不改变线上过关行为。

## 状态与规则

- session 固定选词范围；首轮逐一测所有未过发音的词。
- 首轮结束才集中错词训练；必须播放示范结束并跟读，再独立重测。
- 全部词通过才进入词义测试；没有整体合格率。
- uncertain 保留当前题；网络、服务、噪声错误不得当作答错。
- 发音通过与词义通过分开记录；不能通过只改浏览器 localStorage 绕过。

## 待确定判定方式

现有 Cloudflare Whisper 是转写接口，不是发音评测。不能以识别文本匹配自动发放发音通过记录。

1. 教师课堂判定：服务端仅允许教师授予通过；学生可练习，但不能自认过关。
2. 专业评测：服务端读取冻结的词条及录音，调用配置好的评测服务，再发放通过记录。

## 接入约定

pronunciationPanel 的 onJudge 和 onPractice 必须先保存，再返回服务端状态。
未来的保存接口需要用户/学生/词书快照/序号/轮次/幂等编号；服务端逐项鉴权并锁定当前题。
已过关记录必须按学生、词条内容版本关联，防止词书改词后继承旧通过。
旧测试保持原版本，新测试才启用前置发音；不要中途给旧测试新增无法完成的门槛。

play 必须返回在播放完成后 resolve 的 Promise；播放失败不解锁跟读。
录音只驻留内存，返回页面立即停麦；是否存储原始录音需在接入时按评测服务需要确定。
